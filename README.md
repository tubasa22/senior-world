# OC 시니어 하우징 — 프로젝트 구조 & 유지보수 기준

> 🤖 이 저장소에서 작업하는 AI 에이전트는 AGENTS.md를 먼저 읽을 것.

오렌지카운티 한인 시니어를 위한 주거 정보 사이트.
현재는 **지도 + 신청 안내** 2페이지이며, 이후 **커뮤니티 사이트**로 확장한다.

이 문서는 확장 과정에서 **데이터·마크업이 무거워지지 않고, 손보기 쉬운 상태**를 유지하기 위한 기준이다.
새 페이지나 기능을 붙일 때는 이 문서의 원칙과 폴더 규칙을 따른다.

---

## 1. 핵심 원칙 5가지

| # | 원칙 | 이유 |
|---|------|------|
| 1 | **데이터와 화면을 분리한다** | 아파트 목록 같은 데이터는 HTML 안에 박지 않고 `data/`의 JSON으로 뺀다. 데이터를 고쳐도 HTML은 안 건드린다. |
| 2 | **스타일은 한 곳에서 관리한다** | 색·폰트 같은 디자인 토큰은 `assets/theme.css` 한 파일에만. 페이지마다 복붙하지 않는다. |
| 3 | **페이지는 얇게 유지한다** | 각 HTML은 마크업 + 최소 초기화 코드만. 무거운 로직은 `assets/`의 JS로 뺀다. |
| 4 | **정적 우선(static-first)** | 서버 없이도 동작하게 만든다. 백엔드는 정말 필요할 때(커뮤니티 글 등) 나중에 얹는다. |
| 5 | **점진적 확장** | 기존 파일을 갈아엎지 말고, 새 기능은 새 파일/모듈로 더한다. |

> 한 줄 요약: **"데이터는 data/에, 스타일은 theme.css에, 로직은 assets/에, 페이지는 얇게."**

## 2. 폴더 구조

### 현재 (2페이지)
```
/
├─ index.html      # 지도 (진입점)
└─ guide.html      # 신청 안내
```

### 목표 (커뮤니티 확장 대비)
```
/
├─ index.html            # 지도 (진입점)
├─ guide.html            # 신청 안내
├─ community.html        # (예정) 커뮤니티
│
├─ assets/               # 공용 자산
│   ├─ theme.css         #   디자인 토큰 + 공통 스타일 (모든 페이지 공유)
│   ├─ common.js         #   공통 헬퍼 (전화/길찾기/포맷 등)
│   └─ map.js            #   지도 전용 로직 (index.html에서만 로드)
│
├─ data/                 # 데이터 (화면과 분리)
│   ├─ apartments.json   #   아파트 143건
│   └─ zip-centroids.json#   우편번호 좌표
│
└─ README.md             # 이 문서
```

**규칙**
- 페이지(HTML)는 루트에 둔다.
- 공유하는 CSS/JS는 반드시 `assets/`에.
- 데이터는 반드시 `data/`에 JSON으로.
- 파일명은 **소문자 + 하이픈 + 영문(ASCII)**. 예: `senior-guide.html` (O), `시니어_안내.html` (X — URL 깨짐).

## 3. 데이터 규격 (apartments.json)

아파트 한 건 = 아래 필드를 가진 객체. **이 스키마를 임의로 바꾸지 않는다.** 필드를 늘릴 땐 4장 참고.

| 필드 | 타입 | 설명 | 예시 |
|------|------|------|------|
| `id` | number | 고유 번호 (1부터) | `1` |
| `name` | string | 단지명 | `"Casa Santa Maria"` |
| `address` | string | 도로명 주소 | `"7551 Orangethorpe Ave."` |
| `city` | string | 도시 | `"Buena Park"` |
| `zip` | string | 우편번호 (문자열, 앞 0 보존) | `"90621"` |
| `age` | string | 입주 연령 | `"62+"` |
| `phone` | string | 전화 | `"(714) 994-1404"` |
| `website` | string | 웹사이트 (없으면 `""`) | `"falkenberg-gilliam.com"` |
| `email` | string\|null | 이메일 (없으면 `null`) | `null` |
| `units` | number | 총 세대 수 | `100` |
| `projectBased` | boolean | 저소득 전용(**) 여부 | `false` |
| `fullAddress` | string | 길찾기·지오코딩용 전체 주소 | `"7551 Orangethorpe Ave., Buena Park, CA 92621"` |

**데이터 관리 규칙**
- 아파트 추가/수정/삭제는 **`data/apartments.json`만** 고친다. HTML·JS는 손대지 않는다.
- `id`는 재사용하지 않는다 (삭제해도 번호는 비워둔다).
- `zip`은 숫자가 아니라 **문자열**로 둔다 (`"90621"`의 앞 0 보존).
- `fullAddress`는 `"{address}, {city}, CA {zip}"` 형식을 지킨다 (길찾기·좌표가 여기에 의존).

## 4. 자주 하는 작업 (Recipe)

| 하고 싶은 것 | 고칠 파일 | 방법 |
|-------------|----------|------|
| 아파트 정보 추가/수정 | `data/apartments.json` | 객체 하나 추가·수정. 3장 스키마 준수. |
| 색·폰트 변경 | `assets/theme.css` | `:root`의 CSS 변수만 수정. 전 페이지 일괄 반영. |
| 새 페이지 추가 | 새 `*.html` | 5장의 페이지 뼈대 복사 → `theme.css`·`common.js` 링크. |
| 전화/길찾기 버튼 동작 변경 | `assets/common.js` | 헬퍼 함수 한 곳만 수정. |
| 지도 필터·정렬 로직 변경 | `assets/map.js` | 지도 전용 로직. 다른 페이지 영향 없음. |

원칙: **한 가지를 바꿀 때 한 파일만 열면 되도록** 유지한다. 여러 파일을 동시에 고쳐야 한다면 구조가 잘못된 신호다.

## 5. 새 페이지 뼈대 (복붙용 템플릿)

새 페이지는 항상 이 최소 뼈대에서 시작한다. **스타일·공통 로직은 링크만 하고 페이지 안엔 넣지 않는다.**

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>페이지 제목 | Bridge One</title>
  <link rel="stylesheet" href="assets/theme.css">
</head>
<body>
  <!-- 공통 헤더/네비 (페이지마다 동일하게) -->
  <header class="site-header">
    <a href="index.html">지도</a>
    <a href="guide.html">신청 안내</a>
    <!-- <a href="community.html">커뮤니티</a> -->
  </header>

  <main class="wrap">
    <!-- 이 페이지 고유 내용만 여기에 -->
  </main>

  <script src="assets/common.js"></script>
  <!-- 이 페이지 전용 스크립트가 있으면 여기서만 추가 -->
</body>
</html>
```

## 6. 데이터 불러오기 규칙 (중요)

데이터 접근은 **항상 한 곳(로더 함수)을 통한다.** 이렇게 해두면 나중에
`JSON 파일 → 서버 API`로 바꿔도 **로더 한 곳만** 고치면 되고, 화면 코드는 그대로 둔다.

```js
// assets/common.js
async function loadApartments() {
  const res = await fetch('data/apartments.json');   // 나중에 여기만 API로 교체
  return res.json();
}
```

- 화면 코드는 `loadApartments()`만 호출하고, 데이터가 어디서 오는지는 신경 쓰지 않는다.
- **주의(로컬 미리보기):** `fetch()`로 JSON을 읽으면 파일을 더블클릭해 여는 `file://`에선 막힌다.
  호스팅(http/https)에선 정상 동작한다. 로컬 확인이 필요하면 간단한 정적 서버를 쓰거나,
  임시로 데이터를 `data.js`(전역 변수 할당)로 두는 방식으로 우회한다.

## 7. 현재 → 목표 구조로 옮기는 순서 (마이그레이션)

지금 `index.html`엔 아파트 데이터·좌표·스타일·로직이 **한 파일에 다 들어 있다.**
아래 순서로 조금씩 분리하면 화면 동작은 그대로 두고 구조만 가볍게 만들 수 있다.

1. **데이터 분리** — `index.html`의 아파트 배열 → `data/apartments.json`, 우편번호 좌표 → `data/zip-centroids.json`. `index.html`은 `loadApartments()`로 읽어오도록 교체.
2. **스타일 분리** — `index.html`·`guide.html`의 `:root` 토큰과 공통 스타일 → `assets/theme.css`. 두 페이지는 `<link>`로 참조.
3. **로직 분리** — 지도·필터·지오코딩 로직 → `assets/map.js`. 전화/길찾기/포맷 헬퍼 → `assets/common.js`.
4. **결과 확인** — 화면·기능이 이전과 동일한지 확인.

> 한 단계씩, 각 단계 후 화면이 그대로인지 확인하며 진행한다. 한 번에 갈아엎지 않는다.

## 8. 커뮤니티 사이트 확장 메모

지금은 **읽기 전용 정적 사이트**다. 커뮤니티(후기·문의·게시글 등)는 사용자 입력을
저장할 곳이 필요해지므로, 그때 **가벼운 백엔드**를 뒤에 붙인다. 프런트 구조는 그대로 두는 게 목표다.

- **정적으로 먼저** — 큐레이션한 정보(자주 묻는 질문, 자료 링크 등)는 `data/`의 JSON으로 시작. 백엔드 불필요.
- **입력이 생기면** — 6장의 로더 규칙 덕분에 데이터 출처만 API로 바꾸면 된다.
  백엔드는 무겁게 새로 짓기보다, 기존에 익숙한 스택(예: Google Sheets + Apps Script 엔드포인트)을
  가볍게 얹는 방향을 우선 검토.
- **페이지는 계속 얇게** — 커뮤니티 화면도 5장 뼈대에서 시작하고, 로직은 `assets/`로 뺀다.

### 확장 로드맵 (초안 — 정해지면 채운다)
- [ ] 데이터/스타일/로직 분리 (7장)
- [ ] 공통 헤더/네비 컴포넌트 통일
- [ ] 커뮤니티 페이지 뼈대(`community.html`)
- [ ] 자료실(FAQ·서식·링크) — 정적 JSON
- [ ] 사용자 입력 기능 + 백엔드 (필요 시)

## 9. 코딩 컨벤션 요약

- **파일명**: 소문자-하이픈-영문. `community.html`, `theme.css`.
- **CSS 변수**: 색·간격은 `theme.css`의 `:root`에서만 정의하고 재사용.
- **한 파일 = 한 책임**: 데이터 / 스타일 / 로직 / 마크업을 섞지 않는다.
- **외부 의존성 최소화**: 지금 필요한 것만(지도용 Leaflet, 폰트). 새 라이브러리는 꼭 필요할 때만.
- **주석은 한국어로**, 유지보수 담당자가 바로 이해할 수 있게.

## 10. 실거주자 후기 모듈 (하우징)

지도의 각 단지에 실거주자가 **별점 + 짧은 후기**를 남기는 기능. 첫 동적 기능이며,
이후 IHSS 게시판도 **같은 방식(Sheets 기반 게시 모듈)**으로 복제한다.

### 확정된 설계
| 항목 | 결정 |
|------|------|
| 노출 방식 | **검토 후 게시** — 새 후기는 `검토중`으로 쌓이고, 시트에서 `노출`로 바꿔야 보인다 |
| 작성자 | **닉네임만** (익명 허용, 비우면 `익명`) |
| 카드 표시 | **별점 평균 + 후기 개수만** (예: ★4.2 (8)) |
| 백엔드 | **Google Sheets + Apps Script** (시트 = 관리자 화면) |

### 구성 파일
- `review-backend.gs` — Apps Script 코드. 시트에 붙여넣고 웹 앱으로 배포. `doGet`(승인 후기 반환) / `doPost`(후기 접수, `검토중` 저장).
- `index.html` — 상단 `REVIEW_API` 상수에 배포 URL을 넣으면 활성화. 카드에 별점 배지 + "후기 남기기" 버튼(모달) 추가. **URL이 비어 있으면 후기 UI는 숨고 지도는 그대로 동작**한다(안전한 기본값).

### 데이터 스키마 (reviews 시트)
| 열 | 설명 |
|----|------|
| `id` | 후기 번호 |
| `apartmentId` | 단지 id (apartments 데이터의 `id`와 연결) |
| `rating` | 별점 1~5 |
| `text` | 후기 내용 (최대 1000자) |
| `nickname` | 표시 이름 (비우면 `익명`) |
| `postedAt` | 등록 일시 |
| `status` | `검토중` / `노출` / `숨김` |

### 검토(승인) 방법
후기는 `reviews` 시트에 `검토중`으로 쌓인다. 내용을 보고 `status`를 **`노출`**로 바꾸면
지도 카드에 반영된다. 부적절하면 `숨김`으로 둔다. **별도 관리자 프로그램 없이 시트에서 처리한다.**

### 안전장치 (이미 반영됨)
- 검토 전에는 노출되지 않음 (명예훼손·스팸 차단의 1차 방어)
- 작성 모달에 면책 문구 상시 표시 ("작성자 개인 의견, 본 사이트 입장 아님")
- 스팸 방지용 숨김 필드(honeypot) + 서버측 길이 제한

### 재사용 메모
IHSS 게시판은 이 모듈과 **백엔드 방식·카드 UI가 동일**하다. `review-backend.gs`를 복제해
시트명과 필드(스키마)만 바꾸면 되고, 프런트도 카드 렌더링을 재사용한다.
→ **"Sheets 기반 게시 모듈"을 하나의 패턴으로 유지**한다.

## 11. 수정 이력 (Changelog)

프로토타입 단계에서 발견·수정된 버그를 기록한다. 새 버그를 고칠 때마다 이 섹션에 추가한다.

### 2026-09 — index.html 버그 수정 2건

| 항목 | 내용                                                                           |
| -- | ---------------------------------------------------------------------------- |
| 파일 | `index.html`                                                                 |
| 커밋 | `fix: window.storage를 localStorage로 교체` / `fix: 내선번호 포함 전화번호의 tel: 링크 오류 수정` |

**1)&#x20;****`window.storage`****&#x20;→&#x20;****`localStorage`****&#x20;교체**

- **문제**: `loadCache()` / `saveCache()`에서 사용하던 `window.storage`는 Claude 아티팩트 전용 API로, 실제 배포 환경(GitHub Pages)에는 존재하지 않는다. 매 호출이 예외를 던지고 `catch`로 조용히 무시되어, 좌표 캐시가 저장·복원되지 않았다.
- **영향**: 방문자마다 143개 주소를 매번 Nominatim에 새로 지오코딩 요청 → 불필요한 API 부하, Nominatim 이용약관(초당 1회 제한) 위반 소지, 사이트 IP 차단 위험.
- **수정**: 브라우저 표준 `localStorage.getItem/setItem`으로 교체. `try/catch`는 유지해 시크릿 모드 등에서도 `BAKED_PRECISE` 내장 좌표로 안전하게 폴백.

**2) 내선번호 있는 전화번호의&#x20;****`tel:`****&#x20;링크 오류**

- **문제**: `callHref()`가 숫자와 `+`만 남기는 정규식만 사용해, `"(714) 765-4300 x4810"` 같은 내선번호가 본번호에 그대로 이어붙어 잘못된 링크(`tel:71476543004810`)가 생성됨.
- **영향**: id 12, 140 등 내선번호가 있는 단지 카드의 📞 전화 버튼이 깨진 번호로 연결됨.
- **수정**: `ext.`/`x` 구분자 앞부분만 추출해 본번호만 사용, 10자리 번호는 `+1`을 자동으로 붙여 E.164 형식(`tel:+17147654300`)으로 생성. 내선 없는 번호는 회귀 없이 동일하게 동작.

### Census 배치 지오코딩 스크립트

새 아파트를 추가한 뒤 `node scripts/geocode-batch.mjs`를 실행하면 US Census Bureau Batch Geocoder로 전체 주소를 한 번에 조회한다. 실행 전 `index.html.bak`을 만들고, 기존 좌표를 유지한 채 새로 매칭된 좌표를 `index.html`의 `BAKED_PRECISE` 블록에 병합한다. 실패한 주소는 콘솔에서 확인해 수동으로 보정한다.
